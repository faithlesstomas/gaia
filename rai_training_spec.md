# RAI Training Module Specification & Continuous Learning Loop

## Objective
Enable **RAI** to acting as a self-improving "Brain" server that not only serves LLMs but also **trains** them on data generated by **GAIA** (the "Body").

## Architecture: The "Continuous Learning Loop"

```mermaid
graph TD
    GAIA[GAIA (Guile)] -->|1. Post Trajectories| RAI_API[RAI Server API]
    RAI_API -->|2. Enqueue Job| WORKER[Training Worker (Unsloth)]
    WORKER -->|3. Fine-tune| MODEL[Base Model (Ministral-3b)]
    WORKER -->|4. Save Adapter| ADAPTER[LoRA Adapter]
    ADAPTER -->|5. Hot-Swap| RAI_ENGINE[RAI Inference Engine]
```

## Part 1: RAI Training Module (`src/rai/trainer`)

**Prompt for Developer:**
"Implement a new module `src/rai/trainer` that provides an API for fine-tuning LLMs using Unsloth. This module must be optional (`pip install .[training]`)."

### Key Components

1.  **API Endpoints (`src/rai/server/routers/train.py`)**:
    *   `POST /train/dataset`: Upload formatted ChatML data (from GAIA).
    *   `POST /train/start`: Trigger a training job.
        *   Params: `base_model`, `dataset_id`, `epochs`, `lora_rank`.
    *   `GET /train/status/{job_id}`: Monitor progress (streaming logs).
    *   `POST /models/reload`: Hot-swap the active model adapter.

2.  **Training Worker (`src/rai/trainer/worker.py`)**:
    *   Use `fastapi.BackgroundTasks` or `Celery` (if simple) / `RQ` (Redis Queue).
    *   **Logic**:
        1.  Load `Unsloth` / `FastLanguageModel`.
        2.  Load dataset (convert if needed).
        3.  Run `SFTTrainer`.
        4.  Save adapters to `~/.rai/models/adapters/{job_id}`.
        5.  Update job status.

3.  **Dependency Isolation**:
    *   Training requires heavy libs (Unsloth, Triton, xformers).
    *   Ensure `import unsloth` happens *inside* the worker, not at RAI server startup, to keep inference startup fast.

## Part 2: Hot-Swap Capability

**Challenge**: Ollama doesn't easily support hot-swapping adapters programmatically without restart.
**Solution**: Use RAI's `TorchAdapter` (or create `UnslothAdapter`) for inference.

1.  **New Adapter: `UnslothAdapter` (`src/rai/adapters/unsloth.py`)**:
    *   Inherits from `BaseAdapter`.
    *   Keeps the model loaded in 4-bit.
    *   Implements `reload_adapter(path)` method:
        ```python
        def reload_adapter(self, adapter_path):
            self.model.load_adapter(adapter_path)
            print(f"Hot-swapped to {adapter_path}")
        ```

## Feasibility Analysis

### 1. Unified Repo vs. Separate Repo?
*   **Recommendation**: **Unified Repo (Monorepo)** but **Modular Package**.
*   **Why**: RAI is the "Brain". It should handle both thinking (inference) and learning (training).
*   **Implementation**:
    *   `pyproject.toml`: Add `[project.optional-dependencies] training = ["unsloth", "trl"]`.
    *   Keep training logic in `src/rai/trainer`.
    *   This keeps versioning in sync (e.g., Inference uses v1 format, Trainer produces v1 format).

### 2. MLIR/IREE for Training?
*   **Verdict**: **Too early**.
*   **Reason**: MLIR/IREE is excellent for *inference* optimization (compiling to bare metal/Vulkan). It is NOT yet a mature *training* stack for LLMs. You would lose the massive ecosystem of Hugging Face/Unsloth optimizers.
*   **Path**: Train in Python (Unsloth). Export to GGUF or compiled IREE artifact for Inference.

### 3. Automated Loop
*   **Feasibility**: High.
*   **Risk**: "Catastrophic Forgetting" or "Model Collapse" if training on bad data.
*   **Safeguard**:
    *   GAIA must validate data (already does via `FINAL` signal check).
    *   RAI should keep a "champion/challenger" system:
        *   Train new adapter (Challenger).
        *   Run benchmark.
        *   If Benchmark > Current, promote to Champion.

## Implementation Steps (Prompt for Copilot/Dev)

**User Request**: "Add a training module to RAI."

**Strict Instructions**:
1.  Create `src/rai/trainer` directory.
2.  Add `unsloth` to strictly optional dependencies.
3.  Implement `TrainingService` class that wraps `SFTTrainer`.
4.  Expose `POST /train` endpoint in FastAPI.
5.  Implement `UnslothAdapter` for inference to allow hot-swapping.
